DESIGN MOCKUP — NOT LIVE CODE — Jules, 2026-09-05, REVISED 2026-09-06 What this shows: the "platform loudness fit" idea folded directly into the real, existing Audio Specs card — not a separate table or card. Not merged, no build change. Revision history — read this before reacting to the rows below
  • v1 (2026-09-05) was rejected. It proposed a standalone "Platform Loudness Comparison" card/table (two placement options, a table with column headers, 8 platforms incl. Amazon / Pandora / Deezer). Kevin's verdict: both placements rejected, extra section is "noise," and the platform list should stay at the 6 already defined in the app rather than expanding to loudnesspenalty.com's fuller set.
  • v2 (this version) does four specific things differently, per Kevin's direction:
    • The existing Audio Specs card is reproduced verbatim — same rows, same order, same classes/CSS values, read directly from index.html on main (#mcSpecs, ~line 2609 for markup, ~line 1376–1549 for CSS) — nothing in the existing card is restructured, reordered, or removed.
    • No separate section, card, or heading for platform loudness at all.
    • The 6 platform rows are folded straight into the existing Classified sub-block (the one already holding Genre / Subgenre / Production style / Energy / Mood), styled identically to the Genre row — dot + label + value, nothing more.
    • Only the 6 platforms already in the app's own platform-target selector (#platformSelect, index.html ~line 2183): Trap −8 LUFS, Spotify −14, Apple −16, SoundCloud −10, YouTube −14, Tidal −14. Amazon/Pandora/Deezer dropped — no expansion beyond what already exists in the app.
  • The compactness call (the actual design problem here): six platforms as six separate rows would nearly double the Classified block's height and read as a wall of platform names. Fix: a small 2-column mini-grid for just these 6 rows (3 visual lines, not 6) — reusing the same 2-column rhythm the card's own .mc-rows grid already uses one section up, so it reads as a natural extension of the card's existing pattern, not a bolted-on block. Each row shows just the platform name + the signed dB delta (e.g. "Spotify −5.0 dB"), exactly as terse as the existing "LRA 3.9 LU" rows — target and measured values aren't repeated inline (the Loudness tile above already shows the actual measured LUFS); the dot colour (green/amber/red) carries the pass/moderate/heavy-turn-down read at a glance, the number carries the specific figure.
  • Illustrative dataset (unchanged from v1): a competitively loud trap/club master at −9.0 LUFS integrated — deliberately hot, so the row set shows a realistic split: on-target for Trap (+1.0 dB) and SoundCloud (−1.0 dB), heavy turn-down everywhere else (Spotify/Apple/ YouTube/Tidal, −5 to −7 dB) — the actual pattern a hot trap master produces, not placeholder zeros.
  • Toggle below: Before (today's live Classified block, Genre only) vs After (with the 6 platform rows folded in) — same card, so the addition can be judged in place.
  • Everything outside the Audio Specs card (tab strip, transport, Spectral Balance, Fix Queue, Hope rail) is simplified context dressing only, styled to the same tokens as the live app — not part of this design proposal.
