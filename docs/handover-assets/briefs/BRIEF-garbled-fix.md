# BRIEF — Hope says "I heard “…”. Could you repeat that?" to clear speech (repo /Users/admin/github/aimm, branch garbled-fix)
Bug (Kevin, live): Hope answers perfectly clear statements like "That's fine. No problems. Let's move on to something else." with: I heard “That's fine. No problems. Let's move on to something else.”. Could you repeat that? Cause: hopeTranscriptLooksGarbled (standalone/assets/index.html) splits contractions at the apostrophe ("Let's" -> "Let","s"); the lone "s" has no vowel so the whole sentence is flagged garbled. hopeKnowledgeDecision then returns action 'repeat' (and on the ElevenLabs route the same flag blocks client tool calls). Also the `tool==='transcript'` branch always asks to repeat.
Fix:
1. Tokenise words keeping contractions/possessives whole (/[a-z]+(?:['’][a-z]+)*/gi). Treat text as garbled ONLY if confidence is below the threshold, or it has no readable words, or fewer than half its words contain a vowel. A sentence of 3+ ordinary words must never be flagged. Also count common vowel-less real words (hmm, mm, shh, nth, "tv", "dj", "eq") as readable.
2. Conversational statements (no question/request cue) must never trigger the repeat reply when they are readable; they go through the normal reply path. Audit the other `action:'repeat'` use (the tool==='transcript' branch) and the ElevenLabs-route tool block (search for HOPE_KB_DECISION.garbled) so a readable utterance is never blocked from calling tools.
3. Tests: tests/hope-garbled-speech.test.mjs covering Kevin's exact sentence, other contraction sentences (I'm, don't, it's, we'll, that's), genuinely garbled input ("sss", "ptk bgd"), low confidence still flagged, empty text. Keep existing tests passing; run ALL tests/*.test.mjs.
