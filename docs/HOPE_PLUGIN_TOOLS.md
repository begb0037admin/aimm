# Hope video cueing and ingestion — build 2026-11-23.48 (BUILT, NOT DEPLOYED)

`cue_video(video_id, title?, channel?, switch_to_library?)` accepts an 11-character YouTube ID or an `mwtm-` lesson ID from the KB (`mwtm-<slug>-pNN`) or private manifest (`mwtm-<Set>-NN`). It cues the matching video paused in the Library player without changing the active tab by default, returning `{ok:true,cued:true,video_id,title,transcript_status,tab_switched:false}`. Set `switch_to_library:true` only when Kev asks to see or watch the video. For MWTM, it loads `/mwtm/manifest.json`, matches the set and part number (with a unique title fallback), and selects the private recording through `libPlayerSelect(id,false)`. The KB ID returned by `search_yt_knowledge` or `read_yt_knowledge` can be passed directly to `cue_video`. Title and channel label YouTube videos that are not already ingested. `search_youtube_videos(query)` returns up to five public YouTube results; Hope cues a clear match with `switch_to_library:true` when Kev asks to see or watch it.

`read_video_transcript(video_id, query?)` waits up to 90 seconds for the transcript started by `cue_video` (or starts one peek if called directly). It reuses that result for later questions, selects relevant chunks using the same token overlap approach as `read_yt_knowledge`, and returns up to roughly 4 KB with title, channel and library status. A failed peek returns a spoken-friendly error and is not retried. The Worker uses the same Apify transcript parser as `/kb/add-youtube` and caches new results for one hour in `yt-peek:<id>`; peek does not update the library or vector index. Hope discusses the findings with Kev before adding only on his clear instruction.

When building a chain from a video, Hope verifies Kev's owned plug-ins and favourites, states any swaps, clears and builds the chain on the MixBus in the video's order, and pins settings one plug-in at a time. Only after the chain is on the MixBus does she cue the video without switching tabs. She tells Kev the chain is on the MixBus and the video is cued for when he wants it.

`add_video_to_library(video_id, confirmed)` accepts only an 11-character YouTube ID. Hope calls it only after Kev has heard the transcript findings and clearly says to add it. With `confirmed:false`, it returns the title, channel, library status and a confirmation summary without changing the library. With `confirmed:true`, it uses the same Add to Hope flow as the Library button: `/kb/add-youtube` reuses the peek cache when present, ingests, `loadYtKb()` refreshes the in-page index, and the summary note is attempted. It waits up to three minutes and returns `{ok,video_id,title,already_in_library}` with `error` on failure. It reports success only when the refreshed KB contains the ID. Videos already in the KB return `ok:true` immediately. Hope can then call `read_yt_knowledge(video_id, query)` in the same page session.

The ElevenLabs agent itself remains unchanged until its client tools and prompt guidance are registered there. Run `node scripts/check-mwtm-cue-map.mjs [manifest-path]` to audit the real KB IDs against the private manifest; it reports mapped and unmapped lessons.
