# AIMM plug-in library data and action boundary — Phase 1 requirements

This is the product/privacy requirement derived from PluginHub 2.0.12 and Kevin's decisions. The Phase 2 [architecture](PLUGINHUB_PHASE2_ARCHITECTURE.md) defines the proposed schemas, authentication, retention and transport. The installed app's Worker and cache services were not verified and will not be dependencies.

| Data or action | Source evidence | AIMM placement and rule |
|---|---|---|
| Folder grants, absolute paths, Unused/Trash paths, file sizes, binary hash, raw plist fields | `plugin_scanner.py` snapshot fields; `dashboard_webview.py` move plans | **Mac companion only by default.** The sole exception is a user-requested action preview: only its affected display paths, item/product/format identifiers, version and symlink/permission flags transit the AIMM API in a separately encrypted, owner-unlocked payload. An installer preview additionally carries adapter/artifact identity, official URL and allowed hosts, maximum download size, vendor-published expected artifact digest or reviewed signer, destination and hub identity. These are route policy values, not an installed plug-in's file size or binary hash. Access expires within 10 minutes; the encrypted row is deleted on confirmation/cancellation or swept within one hour after expiry. Installed file sizes/hashes, raw plist, folder grants and unrelated paths are excluded. Paths do not enter ordinary account inventory, Hope tool results, public shares, diagnostics or telemetry. |
| Product identity, vendor, formats, installed version, category, architecture/OS compatibility, check result and source time | Snapshot/report record keys; `run_checks.py` report/category builders | **Companion → AIMM account inventory → website and Hope.** Sync the minimum fields needed for browsing, comparison and grounded recommendations. Include observed source/time/error so Hope cannot claim an unverified update. |
| Saved favourites, tags, collections, hidden products, marks, snoozes and view preferences | `dashboard.html` state paths; `dashboard_webview.py` `save_settings`; browser `localStorage` for some view state | **AIMM account preferences** for cross-device library state; transient panel geometry may stay browser-local. Preserve an observed status separately from user marks and snoozes. Define merge/conflict rules in Phase 2. |
| Vendor login sessions, credentials, entitlement and installed vendor hubs | `dashboard_webview.py` credential/session and `open_hub` methods; `hub_checkers.py` | **Companion/local OS only.** AIMM must not collect vendor passwords or use a static hub map as proof of ownership, login or install completion. |
| Licence keys and attachment files | `license_vault.py`, `keychain_helper.swift` | **Local secure vault only.** Never sync to account or Hope, publish, log, or include in generic diagnostics. Encrypted export/import requires a separate user action. |
| Installer files, queue state, admin authorization, local progress and receipts | `dashboard_webview.py` download/batch methods; `installer_payload.py` | **Companion executes.** AIMM website/Hope may request a scoped action and display progress; a receipt names each attempted path and verified outcome. ## Action contract requirements for Phase 2

1. Pair a specific AIMM account with a specific Mac companion. Each requested action names a product, format and intended operation. The companion resolves that to current local paths, returns a preview, and requires a deliberate confirmation for file changes.
2. Give every action an ID and lifecycle: requested → previewed → authorized → running → completed/partial/failed/cancelled. Return per-path results and a post-action rescan for actions that change inventory. Idempotent retries must not repeat a completed destructive step.
3. Treat the companion as offline-capable. The site and Hope must show the last observed inventory/check time and must not imply a queued request ran while the Mac was unavailable. Define expiry and replay rules before implementation.
4. Keep admin privilege local and scoped to the exact confirmed paths. Reject destination collisions. Verify a cross-volume copy more strongly than a size comparison before removing the source. Prefer recoverable Trash for uninstall and explicit cleanup.
5. Separate the account inventory API, public share API and optional telemetry. Each has its own consent, permitted fields, retention and revocation path. The public share Worker and central cache in PluginHub are reference observations only.

## Evidence limit

Local snapshot key inspection found `path`, `binary_sha256`, `raw_plist_keys`, `mtime` and version/format fields. The saved update report contains `installed_per_format`, `latest`, `is_paid_upgrade`, installer URL and error/context fields. This inspection read field names and aggregate counts only; no licence or vendor secret values were inspected. The exact AIMM JSON schema and retention are Phase 2 decisions, not implied by PluginHub's payload.
