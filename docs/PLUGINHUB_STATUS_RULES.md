# PluginHub status and preference rules — Phase 1

Read-only source trace of the installed 2.0.12 build. These are reference rules to preserve or deliberately improve in AIMM, not evidence that the current remote checker service works.

| Layer | Observed reference rule | AIMM requirement |
|---|---|---|
| Installed state | Scanner records one format bundle per row with name, manufacturer, version fields, architecture and path. A canonical vendor/product view merges format rows. | Keep a product parent with per-format installed versions and file locations; show which format causes an update. |
| Version comparison | `run_checks.py` `compare_versions` (3133) returns unknown if either version is absent/unparseable. If a two-or-more-segment installed version is an exact prefix of a finer latest version, it assumes current to avoid a false update. Otherwise it compares padded version tuples. | Preserve observed strings and a comparison reason; do not invent a latest version from missing data. Allow vendor-specific comparators when justified. |
| Raw check outcome | `build_report` (4294) produces updates, up-to-date, checker errors and unchecked records; saved report counts are 159/100/19/1 at the recorded time. | Separate actual check result from visibility, paid status and user decisions. Show source and timestamp. |
| Paid upgrade | Saved update rows carry `is_paid_upgrade` and sometimes price. Dashboard/menu count treats a paid upgrade separately from a free update. | Keep a paid-upgrade badge and visibility control; never label purchase-required software as a free download. |
| Mark Up to Date | `live_marked_uptodate` in `settings.json` stores the latest version seen when marked. The menu-bar loader expires a mark when a newer latest version arrives (`app.py` 2126 onward); UI handlers are in `dashboard.html` near 15364–15576. | A mark suppresses nagging for that version but must not falsify installed-version readback. Expire it on a newer observed version. |
| Snooze | `snoozed_updates` stores vendor/product, target version and an optional expiry; no expiry means indefinite. Menu-bar count and dashboard use the preference (`app.py` 2103; `dashboard.html` 15340–15419). | Keep expiry and reason visible; count raw and actionable updates separately. |
| Hidden/pinned | Hidden vendors/products and favorites are stored as preferences, not removed from scan. Favorites can be vendors or products (`dashboard.html` 9356–9421, 38067–39106). | Preserve discoverability and undo, and never conflate hide with uninstall. |
| Check cache | Source-defined `run_all_checkers` uses a two-hour default TTL, vendor overrides, local-reader reruns, bounded timeout tiers and no cache write for error-only/timeout results. `run_checks_main` imports absent `cached_checks`; offline mode requests at least 24 hours and no force. | Define AIMM's own cache and offline semantics in Phase 2. Surface last good/current/stale status; do not claim a failed fetch is up to date. |
| Settings persistence | `dashboard_webview.py` `save_settings` (8572) merges under a lock and uses atomic replacement; `dashboard.html` also stores some view state in browser `localStorage`. | Account preference writes need version/conflict handling; local companion settings need atomic writes. Keep transient panel geometry local. |

**Count semantics:** saved `updates_available` is a raw result row count. A displayed “updates available” badge may exclude paid, snoozed or marked rows and may respond to a format filter. AIMM must label raw, free/actionable and filtered counts separately so Hope's answer matches the visible view. No current production badge was invoked to verify its numerical value.

Source: `run_checks.py` `compare_versions`, `run_all_checkers`, `build_report`, `run_checks_main`; `app.py` `_load_snoozed_updates`, `_load_live_marked_updates`, `_load_format_filter`; `dashboard.html` marked/snooze/hidden/favorite functions; aggregate counts from the saved local report.
