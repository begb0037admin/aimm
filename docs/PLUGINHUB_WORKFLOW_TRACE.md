# PluginHub workflow trace — Phase 1

**Status:** partial read-only trace, 2026-10-23. This describes observed reference behaviour and the requirements for an independent AIMM implementation. No PluginHub action was run and no local plug-in was changed.

## Local file management

| Reference action | Observed mechanics | AIMM requirement |
|---|---|---|
| Build move plan | `_build_move_plan` selects existing snapshot paths by vendor, friendly product name and format. The destination is a format-root `(Unused)` folder or a path under a configured offload folder. A configured but unreachable offload folder blocks a move. Destructive callers do not enable cross-vendor fallback. An empty plan means no matching existing files. | Resolve current canonical identity to exact on-disk paths; preview every source, destination, format and collision before confirmation. |
| Move to Unused | `move_plugins_to_unused` combines selected plans, reports moved/errors and can request an admin retry. The reference keeps a move ledger. If an existing destination passes a **size-only** copy check, the non-admin path permanently deletes the active source to finish an earlier move; the admin path can use `rm -rf` for the same purpose. Otherwise it can recycle a stale destination before moving. A cross-volume move copies, checks directories by size, then deletes the source; individual files have no copy verification. | Keep an operation ID and per-path result. Store the original location for restore. Show destination conflicts and any cleanup before acting. AIMM must verify copies more strongly and must not silently delete a source based on equal sizes. |
| Restore | `restore_moved_plugins` reverses recorded paths. It removes an empty destination directory; a populated active-path collision is reported as an error rather than moved into. Permission failures can require an admin retry for unfinished items. | Refuse active-path collisions; do not overwrite or nest bundles. Show partial completion and allow a safe retry of only unfinished paths. |
| Uninstall to Trash | `move_plugin_to_trash` requests macOS recycle so Finder Put Back is available; it returns `trashed`, `errors` and sometimes `requires_admin`. The per-bundle caller polls for up to about one second (20 × 0.05 s); batch/offload paths call `_recycle_and_wait`, whose default timeout is 10 seconds. A slow recycle could therefore look like a permission failure; actual runtime timing was not checked. Earlier paths can already have succeeded. | Preview the exact files. Use recoverable Trash, preserve per-path state and rescan after the action. Verify completion before offering an admin retry. Do not infer all-or-nothing success from a batch-level flag. |
| Remove unused duplicates | `trash_unused_duplicates` recomputes the target set when called and targets only instances marked `unused`. It sets `ok: true` even when `errors` or `requires_admin_paths` is nonempty. Its admin fallback can stage a copy in Trash and then use `rm -rf` on the original when direct root Trash access is unavailable. Staged directories are checked by size only; individual files get no post-copy verification. | Revalidate the exact previewed paths at action time. Require explicit selection/confirmation and inspect every result array. Never report success from `ok` alone. Verify the staged copy strongly before any source removal; active copies must remain untouched. |

Function line numbers refer to this installed build and may move in later releases.

## Profile and public-list sharing

- `build_profile` exports vendor, plug-in name, format, installed version, bundle ID, manufacturer/plugin codes and the scanner's `mtime` as `install_mtime`. The scanner takes the maximum of modification and creation/change time across the bundle directory and selected contents; this is a display date, **not verified installation time**. It omits local paths, raw plist keys and architecture details. **It includes machine label, hostname, macOS version and PluginHub version**, so the reference profile is not anonymous.
- Profile share uses separate create/fetch/revoke/list client calls. Create places the licence key and device ID in the JSON request body; fetch/revoke/list send them in request headers. The client source documents a default seven-day expiry, size and rate caps; the client alone does not prove server enforcement. The five comparison buckets are in sync, version diverged, only remote, only local and format mismatch.
- Public list share is a different endpoint and payload. The UI offers vendor exclusions and optional versions, formats and displayed file dates, but the export also merges `plugins_excluded` utility bundles. It includes a machine label **and hostname**. Source comments disagree on passkey length (four digits versus four to six); the client only strips the supplied value, so server validation and access enforcement are unverified. A short numeric passkey must not be AIMM's only account permission boundary.
- AIMM must specify its own account/device authorization, retention and deletion rules. Sharing is user initiated and separate from routine Hope inventory sync. The public list should omit hostname by default; profile comparison should disclose exactly which machine fields are sent. No licence keys, local paths or vault contents belong in shared data.

## Optional aggregate contribution

`contribute.py` creates a persistent random user ID and exposes `has_opted_in_snapshots`. After a successful check, `app.py` calls both snapshot and report submission helpers when the user has opted in; snapshot submission also runs immediately on opt-in. The report path is limited to roughly one upload per six hours. The payload is not merely aggregate counts: the snapshot retains plug-in names, formats, versions, minimum/SDK OS fields, user category overrides, OS/app versions, submission time and an AAX category mask when available. The report includes unchecked plug-in names/manufacturers, error-vendor plug-in names, update samples with version strings, DAW preference and the persistent user ID. Neither remote retention nor actual anonymity is verified. AIMM's optional contribution must be separate from account inventory sync and public sharing, with the exact fields disclosed and an explicit opt-in. AIMM excludes the AAX category-mask path.
